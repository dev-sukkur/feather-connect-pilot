## 4. Open items

Closed after the first draft of this report, in PR 28 (11 Nov 2026):

| Item | How it was closed |
|---|---|
| Chaos tests | They run on package hosts: runs are queued tagged with the active version, a kill takes the supervisor and its hosts, recovery and sweeps go by the host's id, and the push test posts to a declared webhook |
| Perf tests | The perf project is two packages, push and schedules, neither choosing its flows from the environment at import (the install's load check has a clean one); the push one has a declared webhook, and latency is read from the inbox's `received_at` |
| Deploy test | Passes in CI on PRs 26 and 28; nothing to change |
| CI for PR 26 | Only the chaos job failed, on the two items above. Spool throughput's 1,774 rows/s there came from the stuck chaos processes: the code before and after PR 26 measures the same on one machine |
| Links to packaged names | Links and redirects keep the slash (`/flows/pkg/name`) |
| Packaged backfill and partition check | Run on the version's host (flow packages §12) |

Carried into M2:

| Item | What is left |
|---|---|
| A tick of a packaged flow is a run | A poller of a package queues a run per tick for its host, where M1 kept one stream run a day: a poller every 5 s writes 17,280 runs a day. Bring back the stream run for hosts |
| Packaged datasets in the dashboard | No partition labels and no write cost (flow packages §12) |
| Live Zakya test | Deferred, as above |
