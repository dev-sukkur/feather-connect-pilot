# Feather Connect

An open-source, code-first integration hub covering near-real-time one-to-many data movement, ETL and application integration. Flows are written in Python and run, monitored and operated from one dashboard by developers, operators and AI agents.

> **Status:** milestone M1, at its exit: see the [M1 exit report](docs/06-release/m1-exit-report.md). Start with the [documentation index](docs/README.md).

- **One model for ETL and events:** datasets, partitions, versions and routes.
- **Flows are plain Python:** written by developers or generated by AI.
- **A server-rendered HTML dashboard to monitor and act:** re-run a business slice, replay history, approve postings.
- **Runs anywhere:** `feather dev` on a laptop; Docker Compose with Postgres as the only required database.
- **Environments and tenants:** dev, qa, uat and prod; multi-tenant; an MCP server for AI agents.
- **Licence:** MIT.

## Quick start

You need [uv](https://docs.astral.sh/uv/) and Docker. From a checkout:

```sh
uv sync
uv run feather validate --project examples/demo
uv run feather run orders --project examples/demo --env qa --local --sim
uv run feather dev
```

`feather run` runs the demo flow once on this machine, on simulation stand-ins, and prints what each route applied.
`feather dev` starts Postgres in Docker, the server, a worker and the demo's targets, prints the dashboard's address
and the `dev` user's password, and opens the dashboard. The demo ([examples/demo](examples/demo/README.md)) reads a
shop's orders every minute and delivers them to the `demo.orders` table in that Postgres, a DuckDB file and a small
HTTP API on port 29001. On the dashboard, look at the flow `orders`, its runs, and each route's deliveries; the demo's
README says how to take the API down and watch the other routes carry on.
